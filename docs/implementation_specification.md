## Scope and evidence

This specifies the executable behavior of `HDP-GPC/` at reference commit
`615109a9e474d37626abaff6c51f1c159b26124a`, inspected on 2026-09-24.
It records formulas, ordering, heuristics, stateful shortcuts, and failures found
in the code. A mathematical name or a source comment does not establish that a
conventional probabilistic formula is implemented. Production code and test
baselines were not changed when this reference document was created.

Subsequent structural work delegates maximum shifting, HDP entropy, warp-prior
covariance and monotone-grid arithmetic to private functions while keeping the
old methods. See the [extraction record](../docs/calculation_extractions.md)
for current locations and validation. Historical line references below identify
the reference revision; method names remain the navigation anchors.

See the [implementation map](current_implementation_map.md),
[inference call graph](inference_call_graph.md), and
[characterization documentation](characterization_tests.md) for complementary
inventories and run instructions. This document follows [AGENTS.md](AGENTS.md).

Each numbered behavior has the five requested fields. **Likely purpose** is an
inference, not verified author intent. **Safe to change?** refers to a structural
refactor that must preserve behavior: **no** means an observable contract would
change; **unknown** means more evidence is needed. No listed substantive behavior
is unconditionally safe to change. These judgments do not forbid a separately
approved semantic fix.

Test names below mean `test_<name>` generated by
[test_regression.py](../tests/characterization/test_regression.py) from
[_cases.py](../tests/characterization/_cases.py). A test protects its fixture,
not every branch of its callees. **Indirect** means downstream snapshots capture
some consequences; **none** marks a coverage gap. The suite does not assert object
identity, autograd graphs, memory use, or GPU equivalence.

All 15 tests passed again during this review (30.131 seconds). The earlier
[determinism audit](../tests/characterization/determinism_report.json) reproduced
all snapshots byte-for-byte in three fresh processes, including reversed case
order. The [manifest](../tests/characterization/baselines/manifest.json) records
source hashes and the numerical environment. Discrete values, shapes, dtypes and
nonfinite markers compare exactly; ordinary finite values use `rtol=1e-7`,
`atol=1e-9`. These test tolerances are separate from algorithmic tolerances below.

## Quantities and indexing conventions

| Code | Operational meaning |
|---|---|
| `T`, global `t` | Number/index of observed waveforms, not within-waveform time. |
| `M` | Model count; local score/theta dimensions can additionally include a candidate or remainder state. |
| `gpmodels[ld][m]` | Separate GP/LDS trajectory for output `ld`, cluster `m`. |
| GP `N`, `indexes` | Actual posterior inclusions and recorded global indices; low-SNR index-only inclusion can make their counts differ. |
| `x_basis`, `x_train` | Within-waveform coordinates, distinct from global sample time and cluster-local LDS time. |
| `q[t,m,ld]`, `q_lat[t,m,ld]` | Emission/warp score and latent-dynamics score; `q` is not a state probability distribution. |
| `resp`, `respPair` | Hard state assignments and independently hardened adjacent-state tables. |
| `resplog`, `resp_log` | Shifted log scores, not generally normalized log probabilities. |
| `rho`, `omega` | Beta stick mean and concentration; Beta shapes are `rho*omega` and `(1-rho)*omega`. |
| `Ebeta` | Expected stick weights, optionally including remaining mass. |
| `transTheta`, `startTheta` | Transition/start Dirichlet parameters. `trans_A` and `transPi` hold caller-dependent log quantities. |
| `A`, `Gamma`, `C`, `Sigma` | LDS transition, process covariance, observation map, observation covariance. HDP `gamma` is unrelated to `Gamma`. |
| `f_star`, `cov_f`; `f_star_sm`, `cov_f_sm` | Filtered/smoothed cluster-local histories, including an initial prior entry. |
| `snr_norm` | Output weights; not normalized in every initialization branch. |
| `f_ind_old`, `u_ctrl`, `x_w` | Representative sample indices, unconstrained warp controls, and usually warp displacement (with a disabled-warp exception). |

## A. Model semantics and update ordering

### A01. First cluster and first observation

**Current behaviour:** `M=None` becomes one, `actual_state=0`, `T=0`, histories
are empty, and representatives start at index zero. Each output receives its own
GP/LDS and warper. Initial GP mean is zero and covariance is the kernel evaluated
on basis points. `A=C=I`; dynamic `Gamma=ini_gamma*I`, static `Gamma=0`, and
`Sigma=ini_sigma*I`. Direct emission defaults are `.01I` process and `.25I`
observation covariance. Bayesian dynamics use custom MNIW parameter containers;
static observations initially use an inverse-Wishart container with fixed `C`.
The first online sample skips actual alignment and fits the emission kernel at
its first exact-unit-responsibility inclusion. No online global stick optimization
runs while `M=1`.

**Where implemented:** [GPI_HDP.py](../hdpgpc/hdpgpc/GPI_HDP.py),
`__init__:100`, `include_sample:1906`;
[GPI_model.py](../hdpgpc/hdpgpc/GPI_model.py),
`initial_conditions:115`, `GPR_static:178`, `GPR_dynamic:191`, `include_weighted_sample:353`.

**Likely purpose:** Establish a GP prior, then calibrate its kernel using the first assigned waveform.

**Safe to change? no.**

**Characterization test protecting it:** First-step snapshots in `online_dynamic`,
`online_static`, `online_fast`, `emission_dynamic`, and `emission_static`.

### A02. Subsequent online clusters and the stateful default factory

**Current behaviour:** Default options come from initial cluster zero, using a
cloned kernel and saved initial basis. A birth proposal copies the worst current
emission-ranked model and resets GP/LDS histories. A committed online birth instead
creates a fresh default GP and warper per output. It does not install the proposal
object. `create_gp_default` mutates configuration lists even when constructing
temporary models; its append branch adds sigma bound entries twice. The online
caller also appends a basis separately. Its loop over older observations uses
`posterior=False` without `include_index`, so it does not train the newborn on them.

**Where implemented:** [GPI_HDP.py](../hdpgpc/hdpgpc/GPI_HDP.py),
`set_default_options:468`, `create_gp_default:496`, `create_wp_sys_default:579`,
`include_sample:1990-2123`, `include_sample_fast:2440-2574`.

**Likely purpose:** Compare a reset alternative, then commit a cluster using reusable priors.
Repeated configuration appends have no established purpose.

**Safe to change? no.** Proposal and committed initialization are not interchangeable.

**Characterization test protecting it:** `online_static` produces unforced counts
`[1,1,2,2]` and selected states `[0,0,1,1]`. Configuration-list growth and fast birth
are not directly asserted.

### A03. Offline first group, reallocation, and split initialization

**Current behaviour:** Batch initialization assigns every sample and pair to state
zero. When mean `q` is zero, `estimate_q_first` constructs a default GP, fits the
whole first group and replaces the constructor model. It tries reallocating existing
groups before proposing representative-based splits. Representative-fit scores are
shifted/scaled by their range; emission and latent versions are computed too, but
`q_rank` is assigned the representative-fit score. Equal ranges have no denominator
floor. Candidate grouping uses `isclose(...,rtol=.01)` and bounded exploration via
`n_explore_steps`. A new group uses defaults unless `share_gp` chooses a copied
fitted model. Split acceptance requires strict objective improvement, occupied
groups, and an additional last-group population gate. Accepted representatives
are selected from assigned samples, attempting to avoid duplicate representatives.

**Where implemented:** [GPI_HDP.py](../hdpgpc/hdpgpc/GPI_HDP.py),
`include_batch:805`, `estimate_q_first:1243`, `new_group:1112`.

**Likely purpose:** Fit one population, then explore a small data-driven set of partitions.

**Safe to change? no.**

**Characterization test protecting it:** All five `offline_*` cases finish with two
occupied clusters per output. Constant-score division and `share_gp=True` are untested.

### A04. HDP initialization and remainder dimension

**Current behaviour:** Presets `(gamma,transAlpha,startAlpha,kappa)` are
`less=(.01,.01,.01,0)`, `balanced=(1,1,.1,0)`, `more=(10,10,1,0)`.
With `r=min(.1,1/M^2)`, initial `rho[k]=(1-r)/(M+(-1+r)*k)` and
`omega[k]=1+gamma`. Initial counts are ones and theta is built with dimension
`M+1`. `rho2beta` multiplies each stick by preceding remaining mass and optionally
appends the remainder. `_calcThetaFull` adds counts and stickiness only to the
leading `dimension-1` block/start entries. Its last position remains prior-only
even when a caller passes a dimension equal to existing model count.

**Where implemented:** [GPI_HDP.py](../hdpgpc/hdpgpc/GPI_HDP.py),
`__init__:270`, `init_global_params:353`, `create_initrho:377`,
`_calcThetaFull:400`, `rho2beta:431`.

**Likely purpose:** Preserve tail mass for candidate clusters. Actual passed dimensions
matter more than a generic HDP truncation formula.

**Safe to change? no.**

**Characterization test protecting it:** `hdp_messages` records initial sticks,
weights and theta; inference snapshots record subsequent evolution. Alternative presets are untested.

### A05. Ordering of global variational updates and proposal theta

**Current behaviour:** Each global step computes theta from current sticks, then
optimizes `rho,omega`; no extra theta refresh follows the final stick optimization.
Online commits use four steps for `M>=2`, resetting sticks first with `M-1` when
`M>2`. Offline outer updates reset sticks and use two steps with dimension `M+1`;
the one-cluster offline initialization also does two before local refinement.
`temp_reinit_global_params` extends existing sticks, whereas `reinit_global_params`
resets them. Objective evaluation through `elbo_Linears` constructs temporary theta
without optimizing sticks. Offline `post=True` uses prior plus `.8*old transTheta`
and `.2*new transition counts`; starting theta uses unweighted old-plus-new terms.
Online `one_sample=True` uses `_calcThetaFull` instead.

**Where implemented:** [GPI_HDP.py](../hdpgpc/hdpgpc/GPI_HDP.py),
`reinit_global_params:360`, `temp_reinit_global_params:365`, `_calcThetaPost:383`,
`include_batch:864-911`, `elbo_Linears:1025`, `include_sample:2112-2149`.

**Likely purpose:** Bounded coordinate updates and a distinct proposal-comparison construction.

**Safe to change? no.** Adding a final theta refresh changes the saved state.

**Characterization test protecting it:** `online_static`, all `offline_*` objective
and state traces; `hdp_messages` tests standalone stick optimization.

### A06. Local responsibilities are hard, with independently hardened pairs

**Current behaviour:** Local inference reduces outputs, runs forward/backward
messages and constructs state/pair log scores. `_safe_exp` then returns one-hot
argmax arrays, not exponentials. Ties choose the first index. Pair maximization
flattens `K*K` entries independently of the state marginals, so pair counts need
not match transitions between consecutive hard states. The first pair table is
zero before logarithms; its all-negative-infinity tie chooses the first pair.
Pair hardening explicitly creates float32 arrays.

**Where implemented:** [GPI_HDP.py](../hdpgpc/hdpgpc/GPI_HDP.py),
`_safe_exp:338`, `variational_local_terms:586`, `coupled_state_coef:3651`.

**Likely purpose:** Hard clustering from message-informed scores. Responsibility
terminology must not be interpreted as soft variational inference.

**Safe to change? no.**

**Characterization test protecting it:** `hdp_messages` explicitly includes state
and pair ties; inference traces retain hard/log responsibilities.

### A07. Standard online update sequence and revisiting old states

**Current behaviour:** Normal `include_sample` learning performs this sequence:

1. Increment `T`, replace output weights with ones, append raw observation and coordinates.
2. Assemble per-model histories and optionally align the newest observation.
3. Copy historical emission scores, score the newest sample, and recompute latent
   scores across recorded memberships. Historical emissions are not generally refit.
4. For `t>0`, run local inference and the previous-history objective twice in
   duplicated blocks. Local messages can revise old assignments.
5. Evaluate a provisional birth. If the flattened newest `q_prev` argmax equals
   `self.M`, try absorption candidates in emission rank order; accept the first
   beating the birth objective increment, not necessarily the best candidate.
6. Apply cap/forced-selection logic, commit birth if selected, reorder by population,
   and update global HDP parameters.
7. Re-read the newest assignment, include it in actual emissions, learn Bayesian
   or ML parameters, evaluate the objective, save histories, then optionally update warp memory.

The actual Bayesian commit does not pair-smooth, although hypothetical absorption
models do. Revised old assignments do not cause a general replay of actual GP
histories. `minibatch` affects selected history/ML work, not all retained state.
Warp scores can enter twice: newest `q_aux`/proposal scores already include
`liks[m]`, and calls passing `liks` to `variational_local_terms` add them again
to its cloned final score row. Not all local calls pass that argument.

**Where implemented:** [GPI_HDP.include_sample](../hdpgpc/hdpgpc/GPI_HDP.py#L1906),
`estimate_new:2830`; `GPI_model.smoother_weighted:726`.

**Likely purpose:** Compare incremental absorption/birth while reusing past work.
The duplicated precomparison has no established purpose.

**Safe to change? no.**

**Characterization test protecting it:** `online_dynamic`, `online_static` record
each completed observation and local/objective traces. Minibatches and historical
reassignment edge cases are not isolated; successful repeated warp-score addition
has no dedicated fixture.

### A08. Fast online inference retains historical hard assignments

**Current behaviour:** `include_sample_fast` uses cached `q_last`, `q_lat_last`,
`resp_last`, and `respPair_last`. After initialization it appends forced hard
candidate states/pairs instead of running full historical local inference. Old
assignments persist except for permutations. Latent-score patches use global `t`
and possibly `t-1`, which need not be the previous member of that cluster; patch
exceptions are silently ignored. Candidate totals are detached for comparisons.
The first improving absorption is accepted; actual models are updated afterward,
and detached caches are retained. Cold-start pair initialization differs from
reconstructing pairs from stored labels at row zero.
The first-sample branch appends score/assignment histories and the common tail
appends them again. It computes `model` and `resp_mod` before reordering and uses
them for actual updates afterward without the standard method's re-read.
Its cap fallback uses logs of floored hard assignments rather than the standard
method's pre-hardening log scores, so these cap choices are not equivalent.

**Where implemented:** [GPI_HDP.py](../hdpgpc/hdpgpc/GPI_HDP.py),
`_init_resp_cache_cold_start:2214`, `_ensure_fast_cache_online:2228`,
`_update_q_lat_tail:2273`, `_append_hard_step:2287`, `include_sample_fast:2312`.

**Likely purpose:** Avoid repeated historical inference. Equivalence to standard
online inference is not established.

**Safe to change? no.**

**Characterization test protecting it:** `online_fast` has its own baseline; it
does not assert equality to `online_dynamic`. Fast birth, nontrivial reordering,
cap fallback, reconstruction and swallowed exceptions lack dedicated cases.

### A09. Offline update sequence and replay

**Current behaviour:** `include_batch` increments `T` by batch size, computes
output weights, assigns state zero and optionally reestimates priors. Each outer
iteration refills/stops on empties, initializes HDP if one group, performs local
refinement, updates `M` for a new column, rebuilds counts, resets/updates HDP twice,
updates `trans_A`, and evaluates objective plus entropy. Local work calls
`estimate_q_first` and repeated `estimate_q_all`. Changed memberships cause
copy/reset/replay; identical membership can reuse models and scores.
`full_pass_weighted` includes active observations chronologically. For dynamics it
pair-smooths and Bayesian-updates after every inclusion, then fully smooths and
rescores the supplied batch. Static execution skips that dynamic update block.
The helper does not forward its `snr` argument to inclusion, and explicitly uses
Bayesian dynamic updates rather than implementing a general alternative offline ML schedule.

**Where implemented:** [GPI_HDP.py](../hdpgpc/hdpgpc/GPI_HDP.py),
`include_batch:805`, `variational_local_terms_batch:1170`, `estimate_q_first:1243`,
`estimate_q_all:2844`; [GPI_model.full_pass_weighted](../hdpgpc/hdpgpc/GPI_model.py#L377).

**Likely purpose:** Refit trajectories to changed assignments while reusing unchanged groups.

**Safe to change? no.**

**Characterization test protecting it:** All `offline_*` cases; `emission_dynamic`
separately records filtering and smoothing effects. Offline non-Bayesian execution is untested.

### A10. Historical indexing and retained states

**Current behaviour:** Emission histories use cluster-local time. Exact membership
in `compute_sq_err_all` selects local position plus one; nonmembership selects a
separately clamped preceding position. Sorted indices are assumed. Same-grid samples
with the same selected state/first-observation flag share a scoring covariance.
Latent scores are written only at recorded indices; static and empty models return
zeros. The first latent score uses state `i+1` for both current and previous state
and scales latest `Gamma` by `h_ini`. GP resets can preserve first/last entries and
indices independently while resetting `N=0`. `keep_last_all` is explicit, not
automatic bounded-memory processing.

**Where implemented:** [GPI_model.py](../hdpgpc/hdpgpc/GPI_model.py),
`log_lat_error:288`, `reinit_GP:408`, `compute_sq_err_all:488`,
`compute_q_lat_all:549`, `find_closest_lower:584`; `GPI_HDP.keep_last_all:460`.

**Likely purpose:** Map global samples to sparse cluster trajectories and retain reusable predictions.

**Safe to change? no.**

**Characterization test protecting it:** Indirectly inference and `emission_*`
snapshots. Unsorted indices and keep-last continuation are untested.

### A11. Low responsibility, low SNR, and empty groups

**Current behaviour:** Inclusion requires exact `h==1.0`, despite a `.9` comment.
Batch selection uses `resp>.99` but still enters the exact-unit gate. Nonunit
weights normally record nothing. Unit weight with explicit `snr<=.5` records
indices/data and repeated states without filtering or incrementing `N`.
`refill` swaps an occupied last responsibility column into an empty earlier slot,
or stops when the last slot is also empty. Emergency offline reallocation can
remove the last group when objective gates pass. Removal is distributed across
branches with differing updates to warpers/representatives; there is no common
operation synchronizing every list, tensor and `M`, or general low-mass merge rule.

**Where implemented:** [GPI_model.include_weighted_sample](../hdpgpc/hdpgpc/GPI_model.py#L353),
`full_pass_weighted:377`; [GPI_HDP.py](../hdpgpc/hdpgpc/GPI_HDP.py),
`refill:1076`, `refill_resp:1141`, `remove_last_group:1133`,
`estimate_q_first:1438,1674`, `estimate_q_all:2953`.

**Likely purpose:** Hard membership, low-confidence bookkeeping and recovery from empty groups.

**Safe to change? no.**

**Characterization test protecting it:** Normal zero/unit membership is indirectly
covered. **None** isolates fractional weights, low-SNR inclusion, refill swaps or cluster death.

### A12. Truncation, caps, forced states, and label ordering

**Current behaviour:** Candidate/remainder columns are explicitly added/sliced.
`max_models=None` imposes no user cap. Standard online choices at or beyond the
cap force the best existing log-responsibility choice (fast differs as in A08).
Offline stops on exact
`M==max_models` after local work; it is not a universal preproposal capacity check.
Population sorting changes cluster identities, but `reorder` does not permute all
configuration lists. Forced online selection overwrites newest scores and selected
pair entries, including a self-pair; branches skipping reorder can later use an
unset `reorder` variable. `estimation_limit` limits parameter learning rather than
all filtering, history growth or model dimensions.

**Where implemented:** [GPI_HDP.py](../hdpgpc/hdpgpc/GPI_HDP.py),
`include_batch:927`, `reorder:1091`, `new_group:1112`, `include_sample:2088-2187`;
`GPI_model.bayesian_new_params:966`.

**Likely purpose:** Bound growth, order occupied groups and allow manual assignment overrides.

**Safe to change? no.**

**Characterization test protecting it:** Normal ordering is captured by inference
fixtures. **None** isolates cap boundaries, forced labels or estimation limits.

### A13. Objective composition and small-cluster terms

**Current behaviour:** `compute_q_elbo` sums emission and latent scores only where
`resp==1`. Static/dynamic factors are initialized by self-division of initial
variances, ordinarily one (zero is not guarded). HDP terms scale by basis size
offline and one online. LDS scores use output fractions, that point factor,
cluster population fractions and an extra division by occupied group count offline.
Parameter scores also scale by `100/basis_dimension`. Below `free_deg_MNIV`, the
small-cluster branch still calls `first=False`. Entropy is added separately by
batch drivers. `hmm_switch=False` retains only the latent contribution in the
auxiliary returned objective, but does not globally bypass message passing.

**Where implemented:** [GPI_HDP.py](../hdpgpc/hdpgpc/GPI_HDP.py),
`__init__:179`, `compute_q_elbo:1796`, `full_LDS_elbo:1838`,
`calcELBO_NonlinearTerms:2682`; `GPI_model.return_LDS_param_likelihood:459`.

**Likely purpose:** Balance heterogeneous proposal scores. The ELBO name does not
establish a conventional normalized variational bound.

**Safe to change? no.**

**Characterization test protecting it:** Objective traces in all inference cases.
Disabled HMM, zero initial variance and all-empty objectives are untested.

### A14. Multi-output weights and asymmetric prior estimation

**Current behaviour:** Separate output emissions share one state sequence.
Three-dimensional scores reduce by a weighted sum. Online weights are ones even
when `use_snr=True`. Offline initial SNR compares each waveform with its output's
batch mean using TorchMetrics, then softmaxes over outputs. Disabled SNR starts
with ones, so initially scores sum rather than average. Candidate SNR takes maxima
across clusters then softmaxes over outputs; `normalize_snr` does this even when
SNR is disabled, so later uniform weights can become `1/D`. Two-dimensional
reduction uses aggregate normalized output fractions. `share_gp` copies models,
not a joint-output covariance. Optional output reduction ranks variance of waveform
sums. `redefine_default` uses output zero and its first ten coordinates with
variance factors `.02` for sigma and `.025` for gamma; bounds become
`[1e-5*initial,2*initial]`.

**Where implemented:** [GPI_HDP.py](../hdpgpc/hdpgpc/GPI_HDP.py),
`weight_mean:685`, `reduce_num_outputs:703`, `compute_snr_ini:715`,
`compute_snr:732`, `normalize_snr:750`, `redefine_default:1866`.

**Likely purpose:** Weight useful outputs and share initialization information;
normalization stage changes the balance with HDP/LDS terms.

**Safe to change? no.**

**Characterization test protecting it:** `offline_multi`, `offline_multi_snr`.
Prior reestimation, sharing, output reduction and successful online multi-output are untested.

### A15. Classification is a separate inference path

**Current behaviour:** `cluster_new_batch(learning=False)` scores new observations
against last filtered predictions, computes SNR, runs messages/hardening and
returns labels. It does not refit emissions or activate alignment via `warp` in
that branch. Incremental learning and the two online `classify` branches follow
different control flows; they are not interchangeable read-only interfaces.

**Where implemented:** [GPI_HDP.cluster_new_batch](../hdpgpc/hdpgpc/GPI_HDP.py#L2975),
`include_sample:2078`, `include_sample_fast:2312`.

**Likely purpose:** Label a sequence using existing emissions and transitions.

**Safe to change? no.**

**Characterization test protecting it:** Every `offline_*` case includes postfit
`learning=False` classification. Even `offline_warp` classifies without alignment.
Other classification/continuation branches are untested.

## B. Numerical implementation

### B01. Transition and message normalization

**Current behaviour:** `compute_Pi` returns softmax of `digamma(theta)`.
`compute_trans_A` and standard local start scores use
`digamma(theta)-digamma(sum(theta))`. Other batch/global callers use
`digamma(theta)-log(sum(exp(digamma(theta))))`, sometimes adding `1e-5` inside
the log. Forward/backward/pair routines recompute transitions from
`self.transTheta`, overriding the supplied transition argument. `LogLik` subtracts
a maximum, not log-sum-exp; if any selected maximum is infinite it returns the
whole input unchanged. Forward normalizes each message row by its sum. Backward
normalizes by the sum excluding the final state and ignores supplied forward
normalizers. Pair tables normalize over both state axes before taking logarithms.

**Where implemented:** [GPI_HDP.py](../hdpgpc/hdpgpc/GPI_HDP.py),
`compute_Pi:424`, `LogLik:632`, `variational_local_terms_batch:1170`,
`find_optimum_rhoOmega:2752`, `compute_trans_A:3527`, `forward:3546`,
`backward:3612`, `coupled_state_coef:3651`.

**Likely purpose:** Manage score scale and a distinguished final state. The actual
normalizations are not algebraically interchangeable.

**Safe to change? no.**

**Characterization test protecting it:** `hdp_messages` and inference traces;
pathological all-infinite/zero-message cases are not independently isolated.

### B02. Message floors and entropy protection

**Current behaviour:** Message-local exponentiation subtracts row maxima and uses
`nan_to_num(...,1e-8)`. Forward adds `1e-4` to transition entries below `1e-6`
and initial probabilities below `1e-10`; backward adds it below `1e-5`.
These are additions, not minimum-value clamps. Zero pair denominators become
`1e-10`; entropy helpers use `1e-30`. Impossible state scores and the first
log-pair table can retain negative infinity, which the snapshots encode explicitly.

**Where implemented:** [GPI_HDP.py](../hdpgpc/hdpgpc/GPI_HDP.py),
`calc_Hstart:2690`, `calc_Htable:2694`, `forward:3576`, `backward:3633`,

### B03. GP fitting, constraints and parameter transfer

**Current behaviour:** Default sklearn kernels are `ConstantKernel*RBF+WhiteKernel`,
with white noise initialized at the lower sigma bound. First inclusion fits when
`N==0`, not fitted, and current theta is `allclose` to saved initial theta;
otherwise it performs kernel setup with `valid=False`. `fit_torch` uses a GPyTorch
exact GP for matching grids or a projected inducing-point GP otherwise. Exact
likelihood noise is interval-constrained; differing-grid non-reduced noise is
lower-bounded and that branch explicitly constrains lengthscale. The constructed
`outputscale_constraint` is not attached. The exact branch does not install the
supplied sklearn lengthscale interval, so GPyTorch defaults matter.
Standard exact transfer saves learned outputscale/noise but fixes RBF lengthscale
to **1.2** and does not transfer the learned constant mean. The iterative GP
keeps zero prior mean. `fit_kernel_params` reads learned noise then overwrites it
with `alpha_ini[0][0]` for LDS `Sigma`, resets `A,C` to identity and refreshes the
kernel prior covariance. Kernel noise and LDS observation noise can differ.

**Where implemented:** [GPI_HDP.__init__](../hdpgpc/hdpgpc/GPI_HDP.py#L159);
[GPI_model.py](../hdpgpc/hdpgpc/GPI_model.py), `fit_kernel_params:207`,
`include_weighted_sample:353`; [GPI.fit_torch](../hdpgpc/hdpgpc/GPI.py#L610);
[GPI_models_pytorch.py](../hdpgpc/hdpgpc/GPI_models_pytorch.py#L10).

**Likely purpose:** Fit the spatial kernel while retaining separately specified
LDS noise. The fixed transferred lengthscale has no verified rationale.

**Safe to change? no.**

**Characterization test protecting it:** `emission_dynamic`, `emission_static`

### B04. GP optimizers and stopping

**Current behaviour:** Active fitting minimizes negative exact marginal likelihood
with Adam. Matching-grid exact GP uses learning rate `.1`, budget 4000;
differing-grid non-reduced GP uses selected parameter groups at `.05`, budget 2000;
inducing-point optimization uses `.1` groups, budget 5000. Early stopping begins
only after more than 1000 losses when the sum of ten successive loss differences
is `np.isclose` to zero with `atol=1e-4`. This telescoping test does not require
every difference to be small. Legacy `fit` uses SciPy L-BFGS-B on sklearn log-theta,
up to 50000 iterations, optional random restarts in bounded log space, or explicitly
selected CG/custom optimization.

**Where implemented:** [GPI.py](../hdpgpc/hdpgpc/GPI.py),
`fit_torch:610`, `fit:772`, `_constrained_optimization:1114`.

**Likely purpose:** Initial hyperparameter learning with a practical plateau test.

**Safe to change? no.**

**Characterization test protecting it:** Exact fitting's downstream results in
`emission_*` and inference cases. No direct loss-length assertions or legacy/
projected optimization fixtures exist.

### B05. Emission prediction, covariance and scoring

**Current behaviour:** `log_sq_error` computes
`-.5*(y-mean)' cov^-1 (y-mean) -.5*L*log(2*pi)` without a log determinant.
The shared-covariance batch scorer uses the same convention. On exactly equal
grids, observation prediction returns supplied mean and `Sigma` directly.
On unequal grids with approximately equal `Sigma` diagonal entries, it returns
isotropic covariance even if off-diagonal entries exist. Otherwise it uses kernel
interpolation plus projected `Sigma`. `observe` selects a filtered state;
`observe_last` uses the last smoothed state. `step_forward_last` projects through
`C` without a full `A/Gamma` time prediction. Ordinary scoring therefore does not
generally use `C*P*C'+Sigma`. Latent scoring includes a quadratic residual and
trace term but likewise omits the covariance log determinant.

**Where implemented:** [GPI_model.py](../hdpgpc/hdpgpc/GPI_model.py),
`_gaussian_score_shared_cov:92`, `log_sq_error:250`, `log_lat_error:288`,
`step_forward_last:595`, `observe_last:617`, `observe:626`;
[GPI.pred_dist](../hdpgpc/hdpgpc/GPI.py#L457).

**Likely purpose:** Covariance-scaled matching and inexpensive prediction. Replacing
these expressions with normalized Gaussian densities changes covariance preferences.

**Safe to change? no.**

**Characterization test protecting it:** `emission_*` capture equal/interpolated
observation and latent predictions and scores. Equal-diagonal/nonzero-off-diagonal
and nearly equal grid boundaries lack dedicated cases.

### B06. LDS filter, special first step and smoothing

**Current behaviour:** Filtering predicts `A*mean`, normally uses
`P=A*cov*A'+Gamma`, computes a kernel projection and Kalman gain by solves, and
updates covariance in Joseph form. If `cov_prior` exactly equals a freshly
computed two-argument kernel matrix, it instead uses that prior as `P`, zero
predicted observation, and `kernel(x_train)-kernel(x_train,x_train)` as observation
noise (the white-kernel contribution). This is an equality test, not an `N==0`
flag. Full smoothing revisits cluster-local filtered states using an explicit
inverse for its gain; pair smoothing uses a solve on the last two states.
`smoother_weighted` constructs hypothetical posterior/history values rather than
executing a full backward recursion.

**Where implemented:** [GPI.py](../hdpgpc/hdpgpc/GPI.py),
`posterior:72`, `backward:240`, `backward_notrange:272`;
[GPI_model.py](../hdpgpc/hdpgpc/GPI_model.py), `backwards:687`,
`backwards_pair:705`, `smoother_weighted:726`.

**Likely purpose:** GP-conditioned initialization followed by sequential LDS inference.

**Safe to change? no.**

**Characterization test protecting it:** `emission_dynamic` and dynamic offline
cases retain filtered/smoothed histories; `emission_static` records static filtering.

### B07. Bayesian update gates and deliberately zeroed uncertainty

**Current behaviour:** Bayesian updates require exact unit responsibility and, in
the learning branch, `snr>.5`. Ordinary learning needs `1<N<estimation_limit`;
`force` and full-data options alter the gate. Zero `Gamma` forces static treatment.
Sequential dynamic learning computes state/cross covariance then explicitly
replaces all three covariance terms with zeros. Sequential observation covariance
terms are also zeroed. Full-data updates instead accumulate covariance terms.
Linear algebra failures retain previous parameter distributions. Annealing adds
initial covariance divided by `N^2` (static process covariance uses its initial
value). The parameter limit does not stop filtering. Updated Bayesian `var/y_var`
histories store square-root diagonals, while initialization and ML store diagonals.

**Where implemented:** [GPI_model.py](../hdpgpc/hdpgpc/GPI_model.py),
`bayesian_new_params:966`, `initial_conditions:115`, `new_params:747`.

**Likely purpose:** Stabilize sequential learning and taper initial noise. Zeroing
uncertainty is an approximation that cannot be removed as dead code.

**Safe to change? no.**

**Characterization test protecting it:** Sequential nonannealed behavior in
`emission_*` and inference fixtures. **None** isolates full-data, forced, annealed,
low-SNR, failure fallback or finite estimation-limit updates.

### B08. Custom MNIW and inverse-Wishart conventions

**Current behaviour:** Sequential MNIW averages the new matrix mean with the old
using `(n0-2)` and `(new_n0-2)`. For `n_k==1`, its scale residual is `y1p-y2p`,
not the residual under the newly estimated matrix. Multi-sample residuals use the
new mean. `get_scale(final=False)` returns `scale*n0/(n0-2)`; `final=True` returns
raw MNIW scale. The static inverse-Wishart helper uses `y1-y2`, keeps `C_fixed`,
and always returns scaled covariance, even with `final=True`. MNIW scoring has
quadratic/trace terms without full normalization/determinants. `reinit_LDS`
reconstructs MNIW observation parameters even for a previously static inverse-Wishart
model. No explicit validation prevents `n0<=2`.

**Where implemented:** [GPI_model.py](../hdpgpc/hdpgpc/GPI_model.py),
`reinit_LDS:437`, `matrix_normal_inv_wishart:1280`, `inv_wishart:1417`.

**Likely purpose:** Specialized sequential regularization. A similarly named
distribution in another library is not a drop-in equivalent.

**Safe to change? no.**

**Characterization test protecting it:** `emission_*` and inference distribution/
objective snapshots. Multi-sample posteriors, invalid degrees of freedom and
static-reset equivalence are not separately tested.

### B09. Local jitter and covariance stabilization policies

**Current behaviour:** Stabilization differs by operation:

| Operation | Actual adjustment |
|---|---|
| `_chol_spd` | Symmetrize; add `1e-8*max(mean(abs(diag)),finfo.eps)*I`; one Cholesky attempt, no adaptive retry ladder. |
| First-observation emission score | Add `.01*mean(diag(initial Sigma))*I`. |
| GP posterior/projection | `1e-4*I` in unequal-grid kernel solves; exact-grid identity shortcuts. |
| Observation interpolation | Kernel jitter `1e-4*max(mean(abs(diag(Sigma))),eps)`; general output covariance symmetrized with `1e-6*I`. |
| Latent interpolation | `1e-4*I` for kernel solves, without observation interpolation's final symmetrization/jitter. |
| MNIW posterior | Right-covariance factorization uses `1e-2*max(mean(abs(diag(scale))),eps)*I`; later sufficient-statistic factorization uses `1e-8*I`. |
| MNIW score | Symmetrize `Sigma`, add `1e-8*I`. |
| ML LDS | Determinant/is-close checks trigger `1e-8*I` additions in selected singular cases. |
| Warp prior | Noise plus `1e-6*I`; warp normalization/interpolation denominators use `1e-12`. |

`inv_r` rescales by a power of ten based on maximum diagonal and solves, falling
back to an unscaled solve. `log_det` similarly rescales before Cholesky, with a
determinant-plus-`1e-6` fallback. There is no universal PSD projection.

**Where implemented:** [GPI_model.py](../hdpgpc/hdpgpc/GPI_model.py),
`_chol_spd:83`, `log_sq_error:250`, `posterior:1300`, `log_likelihood_MNIW:1346`;
[GPI.py](../hdpgpc/hdpgpc/GPI.py), `posterior:72`, `projection_matrix:153`,
`new_params_LDS:302`, `pred_dist:457`, `pred_latent_dist:505`,
`log_det:1167`, `inv_r:1201`; `WarpPriorAMTGP._rbf_cov:160`.

**Likely purpose:** Stabilize different algebraic operations at their intended scales.

**Safe to change? no.** A generic stable-solve helper cannot silently replace these policies.

**Characterization test protecting it:** Ordinary numerical results in `emission_*`,
`warper_*` and inference cases. Singular/fallback boundaries and ML stabilization are untested.

### B10. Stick optimization, transforms and failure recovery

**Current behaviour:** Adapted bnpy routines use SciPy `fmin_l_bfgs_b` with analytic
gradients by default. `rho=sigmoid(c_rho)`, `omega=exp(c_omega)`; inverse transforms
are logit/log. `EPS=1e-8` clips rho away from endpoints and lower-bounds initial
omega. Trials use `factr=[1e5,1e7,1e9,1e10,1e11]`, then retry default initialization.
Overflow/NaN and selected solver failures trigger recovery; `warnflag>1`, not every
nonzero flag, is treated as failure. The HDP wrapper retains current sticks if their
length matches `self.M`, otherwise substitutes concentration-based priors.
`beta2rho` floors its denominator at `1e-100`. This NumPy/SciPy boundary does not
carry PyTorch autograd.

**Where implemented:** [OptimizerRhoOmega.py](../hdpgpc/hdpgpc/OptimizerRhoOmega.py),
`find_optimum_multiple_tries:29`, `find_optimum:103`, `c2rhoomega:196`,
`rhoomega2c:217`, bound helpers; `GPI_HDP.find_optimum_rhoOmega:2752`, `beta2rho:441`.

**Likely purpose:** Constrained optimization with progressively relaxed convergence
requirements and continuity after selected numerical failures.

**Safe to change? no.**

**Characterization test protecting it:** `hdp_messages`, `online_static`, offline
stick snapshots. No fixture deliberately forces retries, fallback or clipping boundaries.
The later `HDPComponentTests` in
[`test_hdp.py`](../tests/test_hdp.py) now explicitly exercise those retry,
fallback, clipping and SciPy status boundaries; the original fixtures are unchanged.

### B11. Offline stopping and last-result cache timing

**Current native offline extension:** The historical behaviour below describes
the legacy implementation. Native `_offline.fit` now requires full responsibility
and pairwise stability, finite ELBO stability, and no accepted reallocation or
birth in the current iteration for convergence. Subsequent iterations use the
normal selection path without forced birth exploration. Limit exits refresh
the last-result caches before stopping. See
[offline convergence](offline_convergence.md) for the numerical tolerances.

**Current behaviour:** Outer stopping occurs on refill failure, one sample,
iteration limit, exact cluster cap, more than one empty group, or identical
consecutive assignments. It is not an outer ELBO-tolerance test; the diagnostic
`iteration==14` print does not stop execution. Local refinement uses
`torch.isclose(...,rtol=1e-5)` with default absolute tolerance and counter `i==10`.
Reallocation refinement uses counter 20; split refinement uses 10. Different
initializations/increments mean these counters are not identical requested budgets.
Iteration/cap exits precede the common refresh of `q_last`, responsibilities,
counts and `elbo_last`, so fields may be absent or stale on those exits.

**Where implemented:** [GPI_HDP.py](../hdpgpc/hdpgpc/GPI_HDP.py),
`include_batch:860-947`, `variational_local_terms_batch:1215-1241`,
`estimate_q_first:1374,1724`.

**Likely purpose:** Stop at assignment stability or bound exploration cost.

**Safe to change? no.**

**Characterization test protecting it:** Offline fixtures request three outer
iterations and converge in two. **None** isolates stale-cache early exits,
single-sample, cap or maximum-refinement branches.

### B12. ML LDS schedule, constraints and verbosity

**Current behaviour:** `new_params_weighted` ignores near-zero weights using
`isclose(h,0,rtol=.1,atol=.1)`. It refits between configured sample thresholds or
at periodic multiples; after 500 inclusions the period becomes ten. It fully
smooths before ML reestimation. `new_params` alternates estimation/smoothing for
up to six trials (`N<101`), otherwise four. Convergence requires finite,
nondecreasing likelihood close to the best at relative tolerance `.01`. Only
converged results are installed; otherwise old matrices are repeated. Some
divergence/trial handling is inside `if verbose`, making logging affect execution.
Optional sigma checking clips diagonals to squared exponentiated bounds of the
first kernel parameter, not a general SPD or explicit LDS constraint. ML annealing
uses `initial/(2*N)`.

**Where implemented:** [GPI_model.py](../hdpgpc/hdpgpc/GPI_model.py),
`new_params:747`, `check_bound_sigma:863`, `new_params_weighted:874`;
`GPI.new_params_LDS:302`.

**Likely purpose:** Limit expensive fits and retain old parameters when fitting
does not converge. Logging-dependent control flow has no verified purpose.

**Safe to change? unknown.** This path needs characterization before restructuring.

**Characterization test protecting it:** **None**; fixtures use Bayesian parameters.

### B13. Autograd boundaries, clone/copy and parameter transformations

**Current behaviour:** GP fitting detaches training x/y and clones/detaches basis
points. Learned values transfer through `.item()`, NumPy logarithms and sklearn
log-theta. `GPI.cond_to_numpy` clones/detaches; other conversion helpers have
different policies and some assume CPU tensors. Tensor `clone()` does not detach;
list `.copy()` does not clone elements. Online basis storage explicitly detaches;
fast score/responsibility caches detach but can still share storage with slices.
Warp controls are grad-enabled leaves, warm starts are detached, and final
warp/prior results are produced without gradient tracking. Main inference is not
end-to-end differentiable. Projected fitting sorts basis points and can remove
points using distance compared with the **log** learned lengthscale.

**Where implemented:** [GPI.py](../hdpgpc/hdpgpc/GPI.py),
`fit_torch:610`, `cond_to_numpy:1228`; `GPI_HDP.include_sample:2188`,
`include_sample_fast:2620`, `gpmodel_deepcopy:4037`, conversion helpers at 4085;
`amtgp_warping_system.compute_warp:444,489`, `compute_warp_batch:636,719`.

**Likely purpose:** Separate fitted components and avoid retaining optimization graphs.

**Safe to change? unknown.** Numerical equality alone does not establish equivalent
gradient, aliasing or memory behavior.

**Characterization test protecting it:** Numerical consequences indirectly in

### B14. Dtypes, seeds and determinism boundaries

**Current behaviour:** Importing `GPI_HDP` seeds NumPy/PyTorch with 42, enables
deterministic PyTorch algorithms and sets global default float64. Several other

are float32; integer widths vary. `GPI_models_pytorch.dtype=torch.float32` alone
does not change the global default. Production does not own per-model RNGs,
seed Python `random`, or configure numerical thread counts. Legacy GP restarts
with `random_state=None` consume global RNG; sampling helpers typically default

assumption of CPU/GPU equivalence.

**Where implemented:** [GPI_HDP.py:15](../hdpgpc/hdpgpc/GPI_HDP.py#L15),
`_safe_exp:338`; headers in `GPI.py`, `GPI_model.py`, `GPI_models_pytorch.py`;
`GPI.fit:772`, sampling helpers; `Warping_system.__init__:284`.

**Likely purpose:** Repeatable double-precision research execution with optional GPU support.

**Safe to change? no.**

**Characterization test protecting it:** Every baseline records dtype. The harness
additionally resets Python/NumPy/Torch/Pyro seeds to 42, clears Pyro state and
limits thread pools to one. Those are test settings, not production guarantees.

## C. Caching, reuse and alignment state

### C01. Cached emission work, matrices and messages

**Current behaviour:** Standard online retains historical `q`; fast online also
retains hard assignments and latent scores. `forward` has an append-only branch
when `self.fmsg` is populated, but returns messages without setting that field
itself; initialization sets it to `None`. Same-grid batch emission scoring groups
samples by historical state/first flag and shares a covariance factorization.
`_eye_cache` keys identities by size/device/dtype. The iterative GP stores
`K_X_X`/`K_inv` after fitting, while filtering/prediction also recompute local

**Where implemented:** [GPI_HDP.forward](../hdpgpc/hdpgpc/GPI_HDP.py#L3546),

`OptimizerRhoOmega.flatlowTriIDsDict`, `diagIDsDict`.

**Safe to change? unknown.** Recomputing old scores changes semantics; pure
matrix/index-cache replacements still need precision and ordering checks.

**Characterization test protecting it:** Ordinary numerical reuse is captured by
inference and emission snapshots. **None** explicitly populates `fmsg` or asserts

### C02. Active batch warp cache and incomplete invalidation

**Current behaviour:** `_warp_cache_full[(output,representative_index)]` stores
all-sample displacements, warped signals and scores. Keys omit dataset, grid,
shape, noise, kernel/warper identity, controls, iteration budget and chunk size.
Shape-clearing code is commented out. Models sharing output/representative reuse
the same result. `reset_warp_cache` clears different fields
(`_warp_cache_state`, `_warp_cache_ref`, `_y_trains_w_cache`), not this active

**Where implemented:** [GPI_HDP.py](../hdpgpc/hdpgpc/GPI_HDP.py),

Omitted invalidation inputs have no established mathematical justification.

**Safe to change? unknown.** Correcting invalidation can intentionally change current results.

**Characterization test protecting it:** `offline_warp` captures a fresh model's
one-batch numerical behavior and cache keys. **None** tests reset, changed data,
shape or hyperparameters; this is not a cache-correctness proof.

### C03. Warp-prior factorization cache

**Current behaviour:** `WarpPriorAMTGP` normally normalizes coordinates to `[0,1]`
and builds `omega^2*exp(-distance^2/(2*rho^2))` plus bounded variance-like noise
and `1e-6` jitter. Cholesky/logdet cache keys contain device, dtype, length,
endpoints, rho, omega, noise and normalization flag, but omit interior coordinates
and jitter. A new irregular grid with the same length/endpoints can reuse an old
factor. Prior scores include quadratic, logdet and Gaussian normalization terms,
unlike emission scores.

**Where implemented:** [WarpPriorAMTGP](../hdpgpc/hdpgpc/amtgp_warping_system.py#L106),
`_rbf_cov:160`, `_ensure_cache:175`, `log_sq_error:197`, `log_sq_error_batch:224`.

**Likely purpose:** Cheap repeated displacement scoring under a fixed GP prior.

**Safe to change? unknown.** Altering cache identity needs a deliberate behavior decision.

**Characterization test protecting it:** `warper_batch`, `offline_warp` capture
ordinary prior-score effects. **None** changes interior coordinates/jitter while
preserving the existing key.

### C04. AMTGP warp initialization and monotonic transformation

**Current behaviour:** The main model imports AMTGP, not the legacy GP warper.
Default control count is `max(4,min(8,T))`. Controls start at zero (constant
increments) or previous detached controls when recursive. Scalar control
interpolation uses stored coordinates; batch interpolation uses
`F.interpolate(...,align_corners=True)` over index positions. Increments are
`softplus(u)+1e-6`, cumulatively summed, shifted, divided by their range plus
`1e-12`, and mapped to endpoints. `x_warp=g-x`. Constant increments give a uniform
grid, so zero controls need not mean identity on irregular coordinates. Changing
coordinates without changing length does not refresh the scalar stored grid.
`mode` does not select the legacy mode-specific optimization budgets here.

**Where implemented:** [amtgp_warping_system.py](../hdpgpc/hdpgpc/amtgp_warping_system.py),
`Warping_system.__init__:284`, `_expand_ctrl_to_T:328`, `_monotonic_grid:341`,
`compute_warp:401`, `compute_warp_batch:548`; `GPI_HDP.py:10`.

**Likely purpose:** Ensure ordered coordinates with a small number of free controls.

**Safe to change? no.**

**Characterization test protecting it:** `warper_scalar`, `warper_batch` exercise
nonidentity uniform-grid alignment. Irregular/same-length changed grids, fewer
than four points and legacy-mode equivalence are untested.

### C05. AMTGP objective, constraints and optimization stopping

**Current behaviour:** Adam at `.05` optimizes controls for exactly
`int(train_iter)` iterations, without convergence stopping or best-iterate
restoration. Loss is `.5*SSE/(noise+1e-12)` plus squared second-difference and
displacement penalties (defaults `200` and `1e-3`). Tuple/list/dict theta divides
these penalties by `rho^2+1e-12` and `omega^2+1e-12`; scalar theta leaves defaults.
Scalar noise takes the first supplied element and clamps to bounds; supplied batch
noise uses its mean and clamps. Batch weights clamp negatives to zero and form a
weighted mean with denominator `sum(weights)+1e-12`. Traces hold pre-step losses;
final results use post-step controls. Public default budget is 50; scalar HDP
callers request 250; cached batch uses 50 and chunks of 128. The cached HDP caller
supplies `sqrt(ini_sigma_def)` as data noise, rather than `ini_sigma_def`.

**Where implemented:** [amtgp_warping_system.py](../hdpgpc/hdpgpc/amtgp_warping_system.py),
`_safe_noise:44`, `_theta_to_lambdas:367`, `compute_warp:401`, `compute_warp_batch:548`;
`GPI_HDP.compute_warp_y:3153`, `warp_batch_by_resp_amtgp_cached:3412`.

**Likely purpose:** Fixed-cost penalized alignment. The main scalar lengthscale
argument follows the default-penalty fallback rather than tuning those penalties.

**Safe to change? no.**

**Characterization test protecting it:** `warper_*` record 12-step traces/repeated
calls with scalar theta; `offline_warp` runs the actual 50-step batch default.
Tuple/dict theta, nonuniform noise, negative/zero weights and chunks above 128 are untested.

### C06. Warp scores differ between scalar and batch; recursive memory matters

**Current behaviour:** Scalar alignment returns Gaussian data log likelihood,
subtracting penalties if `bayesian=True`. Batch alignment returns the displacement
GP-prior score instead. The HDP batch caller adds the last warper's prior score
again (`likB+baseB`), so identical priors can be counted twice. Scalar prior theta
is set only on rebuilding for a changed grid length; batch sets it every call.
Recursive scalar calls retain their last controls; batch retains their mean and
replicates it as the next batch's starting vector. `update_warp` only records the
last displacement when recursive, without learning a new warp GP. `reset` clears
warm memory, not the outer full warp cache.

**Where implemented:** [amtgp_warping_system.py](../hdpgpc/hdpgpc/amtgp_warping_system.py),
`compute_warp:489`, `update_warp:525`, `reset:542`, `compute_warp_batch:719`;
`GPI_HDP.warp_batch_by_resp_amtgp_cached:3495-3509`.

**Likely purpose:** Return an alignment compatibility score and warm-start later fits.
Common return names do not imply scalar/batch score equivalence.

**Safe to change? no.**

**Characterization test protecting it:** Two-call `warper_scalar`/`warper_batch`,
plus `offline_warp`. Prior-theta changes, resets and chunk-order effects are not isolated.

### C07. Alignment integration and disabled-warp representation

**Current behaviour:** Offline alignment creates candidate signals for every
output/cluster using its representative waveform/grid, not only assigned samples.
Missing candidate warpers fall back to the last available warper index. Outputs
may receive different warps. The disabled cached path returns expanded original
signals and expanded **input coordinates** as `x_w`, with zero scores; this differs
from the normal displacement convention. The first online warped sample instead
records zero displacement. Online greedy ranking uses output zero and separate
early-exit/score-adjustment heuristics; it is not batch warping one sample at a time.

**Where implemented:** [GPI_HDP.py](../hdpgpc/hdpgpc/GPI_HDP.py),
`include_sample:1941`, `compute_warp_y:3153`,
`warp_batch_by_resp_amtgp_cached:3437`, `select_assigned_warp:3519`.

**Likely purpose:** Compare each observation in representative-specific coordinates,
and bypass optimization cheaply when warping is disabled.

**Safe to change? no.**

**Characterization test protecting it:** `offline_warp`, unwarped offline cases,

## D. State ownership, special cases and unsupported paths

### D01. Model copies and reset/proposal side effects

### D16. Public result reporting does not add probabilistic inference

**Current behaviour:** `HDPGPC.fit` starts a fresh configured model and selects the

Optional prediction calls the existing `observe_last`, preserving its observation
covariance convention (native-basis Sigma, without added latent covariance).

## Refactoring risk priorities and evidence gaps

The ten highest-risk changes are:

1. Softening responsibilities or deriving pair assignments from labels (A06).
2. Unifying standard online, fast online and offline update/replay ordering (A05, A07-A10).
3. Changing reserved-state dimensions, cluster ordering or birth/removal (A02-A04, A11-A12).
4. Adding normalized Gaussian/MNIW density terms or changing objective scaling (A13, B05, B08).
5. Transferring fitted GP parameters conventionally, especially lengthscale/noise (B03).
6. Restoring discarded LDS covariance terms or changing static reset/update semantics (B06-B08).
7. Consolidating normalization, jitter, constraints or optimizer/stopping policies (B01-B04, B09-B12).
8. Making copies independent or changing detach/storage semantics (B13, D01).
9. Unifying scalar/batch/legacy warping, warm starts or cache invalidation (C02-C07, D04).
10. Generalizing multi-output/device paths or fixing recorded failures during a structural change (A14, B14, D02-D03).

The small suite provides numerical evidence for ordinary CPU inference, birth/reuse,
static/dynamic emissions, offline output weighting and AMTGP alignment. It does
not establish behavior on every untested branch. Before changing a listed gap,
add a targeted fixture or explicitly agree on a semantic correction. Regenerating
golden values merely to make a refactor pass does not establish preservation.
